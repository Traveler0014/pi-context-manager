# pi-context-manager

Context visibility and guarded active context management for [pi](https://pi.dev) — know how full the context really is, and compact / prune it on purpose instead of guessing.

给 pi 模型**上下文可见性**（纠偏）与**受控的主动管理能力**（带护栏）。

## Why

Long sessions go wrong quietly: models *believe* their context is nearly full when it is 6–29% used, compaction summaries leave stale self-estimates that anchor hundreds of later turns, and the default `reserveTokens=16384` pushes a 1M-window model's auto-compaction to ~98.4% — always mid-task. This extension adds a near-zero-side-effect **visibility layer** plus three **guarded** management tools.

- Three cache-aware status channels: a window-static system-prompt boot line, append-only milestone messages, and an on-demand read-only tool.
- `context_compact` refuses to run mid-task, inside a cooldown, or below the low-yield threshold (and returns the real usage so the model recalibrates).
- `context_prune` drops stale, already-externalized tool results at a turn boundary and leaves recall refs; it yields automatically when `pi-context-prune` is active.

Full design rationale: [`docs/context-manager-spec/`](./docs/context-manager-spec) (CONSENSUS + RESEARCH) and [`tools/context-manager/README.md`](./tools/context-manager/README.md).

### [tools/context-manager](./tools/context-manager)

给 pi 模型**上下文可见性**（纠偏）与**受控的主动管理能力**（带护栏）。

**Commands:**

- `/context-manager` — Show context-manager status, or run: on | off | threshold <key> <value> | prune on|off

**Tools:**

- `context_status` — Report the exact current context usage: tokens, percent of capacity, remaining before the soft-limit (the auto-compaction threshold), plus the compaction and prune ledger. Read-only. Call this before planning a long task instead of guessing how full the context is.
- `context_compact` — Schedule a compaction that replaces older conversation context with a summary, starting a new context window. It runs as soon as the current turn settles. CALL ONLY AT A TASK BOUNDARY — after a batch of work or a delivered report, never mid-task, and never twice in a row: every compaction invalidates the prompt cache, which is expensive on this provider. Enforced guards: refuses when real usage is below the low-yield threshold (default 50%, returns the real usage so you can recalibrate), refuses within the cooldown after the last compaction (default 10 min), and refuses a keep-list larger than 5% of the context window. Keep-list entries are passed to the summarizer verbatim.
- `context_prune` — Remove old, already-externalized tool results from future context to free space (the raw history is preserved on disk). Requirements, all enforced: (1) externalizedTo is REQUIRED — the file where you saved the original full outputs; (2) only tool results older than the most recent compaction boundary are eligible; (3) per-call quota and a cooldown between batches; (4) every pruned result gets a short recall ref printed so you can read the original later. Use dryRun first to list candidates. Removal is applied at the next turn boundary. Do not prune results you still need verbatim.
